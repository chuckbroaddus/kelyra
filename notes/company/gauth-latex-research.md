## 2. Options (2026)

| Option | License | Expo web | Expo native | Size / speed | Notes |
|---|---|---|---|---|---|
| **KaTeX** (`katex`, MIT) | MIT (Khan Academy) | First-class (`katex.renderToString`) | Needs DOM or WebView | Small, designed for speed | Default `trust: false`. Caps: `maxSize`, `maxExpand`. |
| **MathJax 3** | Apache-2.0 | Yes | WebView | Much larger, slower first paint | Overkill for GAUTH step strings. |
| **react-native-katex** | MIT-ish (npm) | N/A | WebView wrap of KaTeX | Extra dep | Thin WebView; still KaTeX. Prefer **our** WebView + KaTeX CSS rather than an abandoned wrapper. |
| **react-native-math-view / MathJax RN** | varies | Poor | Native views | Extra native code | Avoid: Expo Go + maintenance. |
| **WebView HTML string of model output** | — | — | Yes | — | **Unsafe** if the HTML is the model’s. Never. |
| **Plain Text + no render** | — | Yes | Yes | Zero | Fails the product (raw `$x^2$`). Fallback only. |

**Recommended:** **KaTeX only.** Web: `katex` + `katex/dist/katex.min.css` in a `MathText` helper. Native: same KaTeX via a **tiny** `WebView` (already a dependency) **or** web-only first with native showing source until WebView helper lands in the same loop. Prefer **one helper, both platforms in v1** because parent/teacher Help is phone-heavy.

Do **not** copy SchoolMarm’s KaTeX tree; depend `katex` in class-app `package.json` at implement time.

## 3. XSS / untrusted model (research)

KaTeX docs ([security](https://katex.org/docs/security), [options](https://katex.org/docs/options.html)):

- HTML from KaTeX *should* be free of `<script>` injection **if** generated by KaTeX, not by the model.
- **`trust` default `false`** — keep it. Never `trust: true` (blocks `\includegraphics`, `\htmlClass`, `\href` file:).
- Set **`throwOnError: false`** so bad TeX shows source, not a crash.
- Set **`maxSize`** (e.g. 20em) and keep **`maxExpand`** (default 1000) against `\rule{500em}` / macro loops.
- Error strings may contain unescaped TeX — render errors as **plain Text**, not HTML.
- CVE-class issues exist in *apps* that dump KaTeX errors into innerHTML unsafely (e.g. Open WebUI 2026). Kelyra must not.

**Law:** Model string → **tokenize** delimiters → KaTeX **only** on math spans → insert KaTeX HTML. Never `dangerouslySetInnerHTML` on the whole Explain/Ask blob.

## 4. Phone UX

- Inline math must not clip superscripts; allow horizontal scroll on display-mode `$$`.
- Dark theme: wrap KaTeX in a token color (inherit `color` from `useTheme()`; KaTeX uses `currentColor` for most glyphs). No hardcoded hex except KaTeX `errorColor` mapped to theme danger.
- Web denser; phone readable. No new IconName.

## 6. Recommendation (one line)

**Add `katex` to the class app. One `MathText` helper: split delimiters → KaTeX `renderToString` (`trust: false`, `throwOnError: false`, capped size) on web; same HTML inside existing `WebView` on native. Fallback = original source as `Text`.**
